# 릴리즈 노트: 연결 없는 수동 인계

자동 Excel 연결은 작업 시작의 필수 조건이 아니다. 구현·검증을 진행하면서 입력용 초안을 만들고, 담당자가 실제 공유 파일에 반영한다. 이 도구는 Excel 파일을 읽거나 수정하지 않는다.

## 기록 양식

앱 릴리즈 노트의 7개 열은 `Date | Branch | Version | 작성자 | 분류 | Note | Release Note`다. 실제 입력 전 해당 앱 시트의 헤더·기존 형식·병합 블록을 다시 확인한다.

- Date: 실제 커밋 날짜. 배포 예정일로 바꾸지 않는다.
- Branch/Version/작성자: 확인한 값만 사용한다. Standard/고객 계통, 버전 표기, 영문/한글 작성자 매핑을 추측하지 않는다.
- 분류: F(기능), B(수정), R(리팩토링), F, B(혼합). 내부 변경을 고객 기능 향상으로 꾸미지 않는다.
- Note: 확인한 Jira·요청 업체·모델·기술 내용. Jira를 새로 만드는 권한은 포함하지 않는다.
- Release Note: 한국어 고객용 설명과 항목별 적용 모델·조건. 실제 수행하지 않은 테스트나 적용 범위를 사실처럼 적지 않는다.

커밋별 기록 단위를 유지한다. 같은 버전이라는 이유로 서로 다른 변경을 합치지 않는다. 최신 기록부터 위에 넣되 기존 기록과 중복인지 먼저 확인한다.

## 초안 생성

1. `release-note-input.example.json`을 작업 폴더에 복사한다. 모든 자리표시자를 실제 Git 범위·코드에서 확인한 값으로 바꾼다. 예시 자체는 배포 기록이 아니다.
2. 대상 앱/시트와 최신순 커밋별 records를 입력한다. StartUp은 앱 릴리즈 노트의 StartUp 시트를 사용한다.
3. 아래 명령으로 **새 출력 폴더**에 TSV와 인계 영수증을 생성한다.

```powershell
python tools/workflow/release-note-draft.py --input release-input.json --output release-note-drafts/RELEASE_ID
```

TSV는 UTF-8이며 다중 행 셀은 따옴표로 구분한다. Excel에서 텍스트/TSV 가져오기를 사용하거나 셀별 내용을 확인해 입력한다. 수식으로 해석될 수 있는 선두 문자는 텍스트로 이스케이프한다. 이미 검토한 출력 파일은 덮어쓰지 않는다.

## 담당자의 수동 반영

1. 회사 공유 파일의 해당 앱 시트임을 확인한다. 다운로드한 오래된 사본을 원본으로 오인하지 않는다.
2. 파일 전체의 단독 작성 시간과 동기화 완료를 확인한다. 서로 다른 앱 탭도 같은 워크북이면 작성 시간을 분담한다.
3. 최신 기록의 **병합 블록 전체**를 기준으로 행과 서식을 만들고 이번 값만 입력한다. 기존 기록/설명/서식을 덮어쓰지 않는다. TSV 헤더를 새 열로 추가하지 않는다.
4. 중복·버전·모델·작성자·기존 기록 보존을 확인하고 저장한다. 로컬 저장과 서버 반영을 구분하고, 동기화/담당자 확인 근거를 남긴다.
5. evidence의 `release_notes.excel`에 `status=passed`, 실제 판단자·참조, workbook·sheet·range·verification을 기록한다. 확인하지 못하면 pending 그대로 둔다.

`draft_ready_excel_pending`은 초안만 준비됐다는 뜻이다. Excel 반영 완료가 아니다. 배포 전에는 초안/매뉴얼 검수를 요구하며, 최종 Complete 단계에는 Excel 반영까지 요구한다. 앱 릴리즈와 무관한 SDK-only 작업이면 영향 리뷰와 명시적 적용 제외 근거를 사용한다. 허위 passed를 쓰지 않는다.

## 최초 연결을 나중에 하는 경우

개인 OneDrive 경로·인증·원본 workbook은 Git에 넣지 않는다. 연결 정보를 준비하기 전까지 수동 인계를 사용하면 된다. 선택적으로 `preflight.py --history-dir LOCAL_DIRECTORY`로 **파일 존재만** 확인할 수 있으며, 이 결과가 동기화/서버 최신 상태를 보증하지 않는다. 기존 앱 릴리즈 노트 스킬이 준비된 환경에서는 그 스킬의 조회·동기화·단독 작성 규칙을 추가로 따른다.
