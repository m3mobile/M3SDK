- 범위: PR 전체 변경 파일과 관련 패키지 프로젝트·계약·테스트. 배포/완료 경로는 심화 검토, NuGet 버전 선택과 증거 gate는 집중 재현.
- 작성 변경에 대한 자체 코드 리뷰이며 타인의 승인 리뷰를 대신한 것으로 기록하지 않는다. 최종 수정 head와 CI 실행은 PR 기록으로 확인한다.

## 확인한 문제와 반영

1. **수정 필요 P1 · NuGet 정확한 버전 검사:** PackageReference의 단일 버전 표기는 최소 버전으로 동작한다. 없는 낮은 버전을 요청했을 때 기존 공개 상위 버전으로 대체 복원되는 NU1603을 실제 restore로 확인했다. 정확한 버전 범위로 고정해 미게시 버전은 NU1102로 실패하고 기존 공개 버전은 요청한 버전 그대로 복원되는 것을 확인했다.
2. **수정 필요 P2 · 공개 NuGet 재시도 순서:** Android 의존성 설치의 dotnet build가 명시적 재시도보다 먼저 implicit restore를 실행했다. 격리 restore 재시도가 성공한 후 --no-restore와 동일한 package cache로 의존성 설치·빌드를 수행하도록 수정했다.
3. **수정 필요 P2 · 회귀 생략 증거:** 공백 판단자/참조, 공백·잘못된 타입의 생략 근거, 중복 모델 계획이 허용되는 것을 기존 검증 함수로 재현했다. 필드 타입·내용·계획 중복을 검사하고 회귀 테스트 3개를 추가했다.
4. **기존 경로 개선 · Alpha Xamarin:** 후보 검증 뒤 별도 재빌드하던 Windows/SDK 경로 의존을 제거하고 같은 실행의 검증된 nupkg를 내려받아 사용한다. 정식 배포 완료 근거와는 구분한다.
5. **배포 승인 범위:** 실제 게시와 최종 Release 공개 모두 sdk-release environment를 사용한다.

## 검증

- 공통 정책 단위 테스트 35개 통과. 새 회귀 테스트 3개는 수정 전 코드의 결함을 재현한다.
- 문서 버전 처리 Node 테스트 2개 및 실제 workflow/참고 템플릿 actionlint 통과.
- 공개 NuGet 복원만 사용해 미게시 정확 버전 거부와 기존 정확 버전 선택을 확인. SDK 게시나 기기 접근은 수행하지 않음.
- 최종 head의 원격 CI에서 JVM/API/C# 계약 검사, Maven/NuGet 후보 생성, 양쪽 소비 샘플 및 매뉴얼 PDF 생성을 확인한 후 병합한다.

## 한계와 후속 설정

- 기기 기능·모델별 실기 회귀·실제 공개 패키지 게시·배포 후 실기·Excel 입력은 수행하지 않았다. 이 workflow PR의 검증과 실제 SDK 릴리즈 증거를 혼동하지 않는다.
- GitHub 설정에서 기본 브랜치 필수 CI·승인 리뷰, sdk-release 승인자·허용 브랜치를 별도로 적용·조회한다. YAML만으로 보호 설정이 생기지는 않는다.
- NUGET_API_KEY의 존재는 조회 가능하지만 값을 읽거나 실제 게시로 유효성을 시험하지 않는다.
